# ソフトウェア仕様（WHAT ＋ HOW）

## アーキテクチャ概要

ブラウザだけで動く静的な Web アプリ（ビルドなし）。GitHub Pages から配信し、記録は GitHub の非公開リポジトリ
（データ用リポジトリ）に JSON で置き、GitHub REST API で読み書きする。データ用リポジトリは
「ピアノれんしゅう記録」（`piano-log`）と共有する（→ ADR-0003）。

### レイヤ構成

```
UI 層        index.html / app.js      画面・入力・設定
   │
ロジック層   core.js / calendar.js    判定・集計・取り込み（DOM を触らない。Node.js でテスト）
   │
設定         config.js                既定の項目・色・上限などの値（コードに埋め込まない）
   │
保存先境界   sync.js                  どのファイルに何を読み書きするか（変わった分だけ読む・記録単位のマージ）
             ghstore.js               GitHub とのやりとり・接続コード・ファイルの形（piano-log と共通）
             localStorage             端末内の控えと、まだ送れていない記録
```

### モジュール責務

| モジュール | 責務 | 対応仕様 |
|---|---|---|
| `core.js` | 日付、起床の判定、ピアノの自動集計、項目の状態、月・年の集計、連続日数、取り込みファイルの検査 | 判定・集計 |
| `calendar.js` | 日本の祝日（`piano-log` と同じもの） | 起床の判定 |
| `config.js` | 既定値（項目の初期セット、色、ピアノアプリの URL、送信の分割数） | 設定 |
| `app.js` | 画面の描画、入力、設定、送受信のタイミング | 入力・一覧・設定・取り込み |
| `sync.js` | 保存先から変わったファイルだけ読む、記録を人 × 年のファイルにマージして書く | 同期のマージ |
| `ghstore.js` | GitHub REST API の呼び出し、接続コード、データ用リポジトリのファイルの形（`piano-log` と同じ内容） | 保存先 |

### 起動シーケンス

1. `config.js` の既定値と、端末内（localStorage）の設定・記録・待ち行列を読む
2. 端末内の内容で画面を描く
3. 設定用リンク（`#c=KIROKU1:…`）があれば保存先につなげ、アドレス欄から消す
4. 保存先があれば、まだ送れていない記録を送ってから、変わったファイルを読み直し、画面を描き直す

## データ

### データ用リポジトリのファイル（`ghstore.js` の `Layout`）

| パス | 中身 | 書くアプリ |
|---|---|---|
| `routine/config.json` | 習慣の設定（人と項目） | 習慣きろく |
| `routine/<人ID>/<年>.json` | その人のその年の記録。1日 1行 | 習慣きろく |
| `piano/settings.json` | ピアノアプリの設定（人・目標・使いはじめた日 `since`） | piano-log |
| `piano/records-<年>.json` | その年の練習の記録。1回 1行 | piano-log |

習慣きろくは `piano/` を読むだけ、piano-log は `routine/` に触れない。

### 設定（`routine/config.json`）

```
{ schema: 1, updatedAt: <ms>,
  people: [ { id, name, color, pianoId, items: [ item… ] } ] }
```

- `id` … 人の ID。ピアノアプリの人から作ったときは同じ ID（`p1` など）。
- `pianoId` … ピアノアプリ側の人の ID。空ならピアノを自動集計しない。
- `item` は種類ごとに次の形。`id` は人の中で一意。`note` は項目の説明（ルール）で任意。

| type | 意味 | 固有の値 |
|---|---|---|
| `time` | 時刻を入力し、基準と比べて判定する | `limitW`（平日の基準 `HH:MM`）、`limitH`（休日の基準） |
| `choice` | 選択肢から選ぶ（選択肢なしなら「できた」だけ） | `options`（文字列の配列） |
| `piano` | ピアノアプリの練習時間を自動集計する | `goalMin`（目標の分） |

### 記録（`routine/<人ID>/<年>.json`）

```
{ "schema": 1, "person": "p1", "year": 2026,
  "days": {
    "2026-11-16": { "wake": ["done", "06:20", "<更新日時>"], "memo": ["", "本文", "<更新日時>"] },
    …
  } }
```

- 1日 = 1行。項目 ID ごとに `[結果, 内容, 更新日時]`。
- 結果は `done`（できた）／`fail`（失敗）／`''`（未入力）。内容は時刻（`HH:MM`）、選んだ選択肢、メモの本文など。
- 更新日時は ISO 8601（UTC）。同じ日・同じ項目は、これが新しい方を残す。
- 日ごとのメモは、項目 ID `memo`（結果は空、内容が本文）。
- アプリの中では、1件を `{ id, date, person, item, result, value, updatedAt }`（`id` = `<日付>_<人ID>_<項目ID>`）として扱う。

### 接続コード

`KIROKU1:` ＋ `{ o: ユーザー名, r: リポジトリ名, t: トークン }` の JSON を base64url にしたもの。
トークンは fine-grained personal access token（対象はデータ用リポジトリだけ、Contents の読み書きだけ）。
端末の localStorage にだけ保存する。設定用リンクは `<アプリの URL>#c=<接続コード>`。

### GitHub API の使い方（`ghstore.js`）

| 操作 | 呼び出し |
|---|---|
| ファイルの一覧（パスと sha） | `GET /repos/{o}/{r}/git/trees/{branch}?recursive=1` |
| 一覧にあるファイルの中身 | `GET /repos/{o}/{r}/git/blobs/{sha}` |
| 書く前に、いまの中身と sha | `GET /repos/{o}/{r}/contents/{path}` |
| 書く（sha が違えば 409） | `PUT /repos/{o}/{r}/contents/{path}` |

エラーは種類に分ける：`offline`／`auth`（401）／`forbidden`／`ratelimit`／`notfound`／`conflict`／`server`／`format`。

## 振る舞い（behaviors）

### 起床の判定

- **satisfies**: R-6
- **モジュール**: `core.js`（`judgeTime`）
- **シーケンス**: その日が休日（土日・祝日）なら `limitH`、それ以外は `limitW` を基準にする。
  入力した時刻が基準**以下**なら「できた」、遅ければ「失敗」。基準が空なら、時刻を入れた時点で「できた」。
  判定のあと、結果は手で切り替えられる（切り替えた結果がそのまま保存される）。
- **Acceptance**:
  1. 平日・基準 06:30 で 06:30 → できた、06:31 → 失敗
  2. 土曜・祝日・振替休日は休日の基準で判定する
  3. 判定後に結果を手で変えると、時刻はそのままで結果だけ変わる

### ピアノの自動集計

- **satisfies**: R-3, R-13
- **モジュール**: `core.js`（`pianoIndex`、`itemState`）
- **入力**: ピアノアプリの記録（`piano/records-<年>.json` の `date`、`people`、`sec`）と設定（`piano/settings.json`）の `since`（使いはじめた日）
- **シーケンス**: 人の `pianoId` を含む記録の秒数を日ごとに合計する（連弾は全員に入る）。
  - その日に練習があるか、その日がピアノアプリを使いはじめた日以降なら**自動**：
    合計が目標以上で「できた」。届かないまま日付が過ぎたら「失敗」。今日でまだ届いていなければ未入力（途中）。
  - それ以外（ピアノアプリを使う前の日）は、保存されている記録（過去の取り込み分）をそのまま表示する。
    使いはじめた日以降でも、その日に練習の記録がなく、保存されている結果（取り込み分）があれば、それを表示する。
  - 自動の日は、ピアノの欄を手入力できない。アプリを使わずに練習した日は、ピアノアプリの「手で追加」で入れる。
    自動でない日（使う前の日、ひも付けのない人）は、○／× を手で変えられる。
- **Acceptance**:
  1. 同じ日の記録 2件（6分・5分）、目標 10分 → 11分・できた
  2. きのう 3分、目標 10分 → 失敗。今日 3分 → 未入力
  3. 使いはじめた日より前で練習なし・取り込みずみ「5分 ○」→ その記録を表示
  4. `pianoId` が空の人は自動集計しない
  5. 使いはじめた日以降で練習なし・取り込みずみ「10分 ○」→ その記録を表示。練習の記録が入ったら自動に切り替わる

### 入力（きょう）

- **satisfies**: R-2, R-5, R-10, R-11
- **モジュール**: `app.js`
- **シーケンス**: 人を選び（端末が覚える）、日付を選ぶ（はじめは今日）。項目ごとに
  - `time`：時刻を入れる（「いま」ボタン、よく使う時刻のボタン）。入れた瞬間に判定して保存
  - `choice`：選択肢を 1タップで「できた」。「失敗」ボタン。もう一度押すと未入力に戻る。「ほか」で自由入力
  - メモ：入力がとまったら保存
  変更は端末内に保存してすぐ画面に出し、少し待ってから保存先へ送る。
- **エラー処理**: 送れなかった分は端末に残し、次に開いたとき・つながったときに送る。件数を画面に出す。
- **Acceptance**:
  1. 選択肢を押すと、その日のその項目が「できた・内容＝選択肢」になる
  2. 同じ選択肢をもう一度押すと未入力に戻る
  3. 通信できないとき、入力は端末内に残り、あとで送られる

### 同期のマージ

- **satisfies**: R-4, R-11
- **モジュール**: `sync.js`（`pull`、`pushEntries`、`pushConfig`）、`ghstore.js`（`update`）、`app.js`（送るタイミング）
- **シーケンス**:
  - **読む**：ファイルの一覧を取り、前に読んだときと sha が違うファイルだけ中身を読む。
    読んだファイル（人 × 年）の記録で端末内の同じ人・同じ年を置きかえ、まだ送れていない記録を上にのせる。
    途中で読めないファイルがあれば、何も覚えずにやり直す。
  - **書く**：入力から少し待ち（続けてタップした分をまとめる）、人 × 年のファイルごとに
    「いまの中身を読む → 記録単位で更新日時が新しい方を残す → sha 付きで書く」。ほかの端末が先に書いていたら（409）読み直してやり直す。
    中身が変わらないときは書かない。
  - 設定は `updatedAt` が新しい方を残す。
  - 端末をつなげる前に入れた記録は、つなげたときにまとめて送る。
- **エラー処理**: 通信できないときは、送れていない件数を出して、つながったら送る。
  接続コードの期限切れ（`auth`）などは、設定を見るよう文字で案内する。入力した記録は端末に残る。
- **Acceptance**:
  1. 古い更新日時の記録を送っても、新しい記録は上書きされない
  2. まだ送れていない記録は、読み直したあとも画面に残る
  3. 2台が同時に別の項目を書いても、両方の記録が残る
  4. 何も変わっていなければ、読み直しは一覧の 1回だけで終わる
  5. トークンが無効なら `auth` として案内を出す

### 月の一覧・達成率

- **satisfies**: R-8, R-20
- **モジュール**: `core.js`（`monthSummary`、`streak`）、`app.js`
- **シーケンス**: 選んだ人・月について、日 × 項目の表を出す。項目ごとに できた／（できた＋失敗）を達成率とし、
  未入力の日は分母に入れない。年の画面では 項目 × 月 の達成率を並べる。
  連続日数は、今日（今日が未入力ならきのう）からさかのぼって「できた」が続いた日数。
- **Acceptance**:
  1. できた 20・失敗 5・未入力 5 → 達成率 80%
  2. 今日が未入力で、きのうまで 3日連続できた → 連続 3日

### 過去の記録の取り込み

- **satisfies**: R-9, R-12
- **モジュール**: `impl/tools/convert_original.py`（変換）、`app.js`（取り込み）
- **シーケンス**: 元の記録（リポジトリには入れない）を変換ツールで取り込みファイル（JSON）にする。
  アプリの設定で、ファイルと取り込む人を選ぶと、記録をまとめて保存先へ送る（年ごとに 1回の書き込み）。
  ファイルに項目の設定（選択肢・説明）があれば、その人の項目に反映するか選べる。
  同じ日・同じ項目にすでに記録があるときは、取り込みの方を新しい記録として上書きする。
- **取り込みファイル**: `{ format:'routine-import', version:1, items:[…], entries:[{ date, item, result, value }] }`
- **Acceptance**:
  1. `format` が違うファイルは取り込まない
  2. 取り込んだ記録は、選んだ人の ID で保存される
