# 習慣きろく（Routine）

家族それぞれの毎日の習慣（起床・運動・柔軟・英語・ピアノなど）を記録して振り返る Web アプリです。
ピアノは「ピアノれんしゅう記録」（`piano-log`）の練習時間が自動で入ります。
`spec/`（仕様＝SSOT）と `impl/`（実装）を統合した mono-repo。

## 使い方

- **日**：人を選び、項目ごとにタップして記録します。日付は ◀ ▶ か、日付を押して選びます（過去の日も直せます）
  - 起床：時刻を入れると、基準時刻（平日・休日で別）と比べて ○／× を自動で付けます。例外の日は ○／× を押して変えられます
  - 運動・柔軟・英語など：したことを 1タップ。「ほか…」で自由に書けます。できなかった日は「× 失敗」
  - ピアノ：ピアノれんしゅう記録の練習時間の合計が自動で入り、目標に届くと ○ になります（手入力はいりません）
  - メモ：できなかった理由など。入力がとまると保存されます
- **月**：その月の達成率と、日ごとの一覧表。行を押すとその日の入力に移ります
- **年**：項目 × 月の達成率と、つづいている日数
- **設定**（右上の歯車）：人の追加・名前・色、人ごとの項目（名前・入力のしかた・選択肢・基準時刻・目標・説明）、
  記録の保存先、過去の記録の取り込み

達成率は できた ÷（できた＋失敗）です。未入力の日は数えません。

## 記録の保存先（Google スプレッドシート）

記録は、ピアノれんしゅう記録と**同じスプレッドシート**に保存します（シート「習慣」が増えます）。
スプレッドシートはあなたの Google ドライブにあり、アプリは「ウェブアプリの URL」を通して読み書きします。
URL を設定した端末なら、どれからでも同じ記録が見えます。設定しないあいだは、記録はその端末の中だけに残ります。

### すでにピアノれんしゅう記録でスプレッドシートを使っているとき

1. 習慣きろくの 設定 →「スプレッドシート用プログラムをコピー」を押す
2. スプレッドシートを開き、「拡張機能」→「Apps Script」で、いまのコードを全部消して貼り付け、保存
3. 「デプロイ」→「デプロイを管理」→ 鉛筆のボタン → バージョンを「新バージョン」にして「デプロイ」
   （URL は変わりません。ピアノれんしゅう記録はそのまま使えます）
4. 習慣きろくの 設定 →「記録の保存先」に、ピアノれんしゅう記録と同じ URL（…/exec）を入れて「つなげる」

### はじめてスプレッドシートを作るとき

1. Google ドライブで新しいスプレッドシートを作る
2. 「拡張機能」→「Apps Script」を開き、最初のコードを消して、コピーしたプログラムを貼り付けて保存
3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」、
   「次のユーザーとして実行：自分」「アクセスできるユーザー：全員」で「デプロイ」
4. Google の確認画面で自分のアカウントを選んで許可する
5. 表示された「ウェブアプリの URL」（…/exec）を、両方のアプリの設定に入れる

ほかの端末には、設定 →「設定用リンクをコピー」で作ったリンクを送ると、開くだけで保存先が設定されます。
URL を知っている人は記録を読み書きできるので、家族以外には教えないでください。

## 過去の記録の取り込み

メモやスプレッドシートに付けていた記録は、変換ツールで取り込みファイルにしてから、アプリに取り込みます。
元の記録と取り込みファイルは `original/` に置き、リポジトリには入れません（`.gitignore` 済み）。

```powershell
python impl/tools/convert_original.py    # original/ → original/routine.import.json
```

アプリの 設定 →「過去の記録を取り込む」で、取り込む人とファイルを選んで「取り込む」。
変換ツールは、推測して取り込んだところ（その日に書かれていなかった項目など）を最後に一覧で出します。

## 開発

```powershell
node --test "impl/tests/*.test.js"        # テスト
node impl/tests/mock-server.js --demo     # http://localhost:8765/ （偽の保存先つき。保存先は http://localhost:8765/exec）
```

## 読む順序

1. `CLAUDE.md` — ルール・技術スタック・Git運用（Claude Code は最初にこれを読む）
2. `spec/requirements.md` — なぜ作るか・目標値・NFR
3. `spec/glossary.md` — 用語
4. `spec/software.md` — 仕様本体
5. `STATUS.md` — 今どこ・次に何を

## ディレクトリ構成

| パス | 役割 |
|---|---|
| `spec/` | 仕様（SSOT）。人間とAIの合意対象 |
| `spec/decisions/` | ADR — 判断の履歴 |
| `impl/src/` | アプリ本体（GitHub Pages で公開する中身） |
| `impl/src/apps-script.gs` | スプレッドシート側のプログラム（`piano-log` と共通） |
| `impl/tests/` | テストと、偽の保存先つき開発用サーバー |
| `impl/tools/` | 過去の記録の変換ツール |
| `original/` | 元の記録（リポジトリには入れない） |
