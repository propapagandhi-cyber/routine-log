# 習慣きろく（Routine）

家族それぞれの毎日の習慣（起床・運動・柔軟・英語・ピアノなど）を記録して振り返る Web アプリです。
ピアノは「ピアノれんしゅう記録」（`piano-log`）の練習時間が自動で入ります。
`spec/`（仕様＝SSOT）と `impl/`（実装）を統合した mono-repo。

## 使い方

- **日**：人を選び、項目ごとにタップして記録します。日付は ◀ ▶ か、日付を押して選びます（過去の日も直せます）
  - 起床：時刻を入れると、基準時刻（平日・休日で別）と比べて ○／× を自動で付けます。例外の日は ○／× を押して変えられます
  - 運動・柔軟・英語など：したことを 1タップ。「ほか…」で自由に書けます。できなかった日は「× 失敗」
  - ピアノ：ピアノれんしゅう記録の練習時間の合計が自動で入り、目標に届くと ○ になります（手入力はいりません）
  - メモ：できなかった理由など。入力がとまると保存されます
- **月**：その月の達成率と、日ごとの一覧表。行を押すとその日の入力に移ります
- **年**：項目 × 月の達成率と、つづいている日数
- **設定**（右上の歯車）：人の追加・名前・色、人ごとの項目（名前・入力のしかた・選択肢・基準時刻・目標・説明）、
  記録の保存先、過去の記録の取り込み

達成率は できた ÷（できた＋失敗）です。未入力の日は数えません。

## 記録の保存先（GitHub の非公開リポジトリ）

```
公開リポジトリ   routine-log / piano-log … アプリ本体（GitHub Pages で配信）。記録は入っていない
非公開リポジトリ Routine-data            … 習慣とピアノの記録（JSON）。家族以外は見えない
トークン（データ用リポジトリだけ読み書きできる鍵） → 「接続コード」にまとめて、各端末に 1回貼る
```

端末で GitHub や Google にログインする必要はありません。接続コードを貼った端末なら、どれからでも同じ記録が見えます。
つなげないあいだは、記録はその端末の中だけに残ります（あとでつなげると、まとめて送ります）。

### 1. トークンを作る（設定する人が 1回だけ）

1. GitHub 右上のアイコン → **Settings** → 左下 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. 次のとおり設定する

| 項目 | 値 |
|---|---|
| Token name | `routine-data` など |
| Expiration | 選べる範囲でいちばん長く（期限が来たら作り直す） |
| Repository access | **Only select repositories** → `Routine-data` だけ |
| Permissions → Repository permissions → **Contents** | **Read and write** |

3. **Generate token** → 表示された `github_pat_…` をコピー（この画面を閉じると二度と表示されない）

### 2. 接続コードを作って、つなげる

1. 習慣きろくの 設定 →「記録の保存先」→「接続コードを作る（設定する人向け）」を開く
2. GitHub のユーザー名、データ用リポジトリの名前（`Routine-data`）、トークンを入れて「接続コードを作る」
3. 上の欄に `KIROKU1:…` が入るので「つなげる」

### 3. ほかの端末・ピアノれんしゅう記録

- **習慣きろく**：設定 →「設定用リンクをコピー」で作ったリンクを送り、その端末で開く（または接続コードを貼る）
- **ピアノれんしゅう記録**：習慣きろくの「接続コードをコピー」でコピーした接続コードを、ピアノれんしゅう記録の
  設定 →「記録の保存先」に貼る。同じ接続コードを使います

接続コードと設定用リンクは**パスワードと同じ**です。家族以外には送らないでください。

### 困ったとき

| 症状 | 対処 |
|---|---|
| 「接続できません（接続コードの期限切れかもしれません）」 | トークンの期限切れ。手順 1 で作り直し → 手順 2 で新しい接続コード → 各端末に貼り直す（端末の記録は消えない） |
| 「まだ送れていない記録が ○件あります」 | 電波が戻れば自動で送る。何もしなくてよい |
| 端末をなくした | GitHub の Fine-grained tokens でそのトークンを **Delete** し、新しいトークンと接続コードでつなぎ直す |
| まちがえて消した・書きかえた | `Routine-data` の **History** に変更の履歴が残っているので、前の内容に戻せる |

## 過去の記録の取り込み

メモやスプレッドシートに付けていた記録は、変換ツールで取り込みファイルにしてから、アプリに取り込みます。
元の記録と取り込みファイルは `original/` に置き、リポジトリには入れません（`.gitignore` 済み）。

```powershell
python impl/tools/convert_original.py    # original/ → original/routine.import.json
```

アプリの 設定 →「過去の記録を取り込む」で、取り込む人とファイルを選んで「取り込む」。
変換ツールは、推測して取り込んだところ（その日に書かれていなかった項目など）を最後に一覧で出します。

## 読む順序

1. `CLAUDE.md` — ルール・技術スタック・Git運用（Claude Code は最初にこれを読む）
2. `spec/requirements.md` — なぜ作るか・目標値・NFR
3. `spec/glossary.md` — 用語
4. `spec/software.md` — 仕様本体
5. `STATUS.md` — 今どこ・次に何を

## ディレクトリ構成

| パス | 役割 |
|---|---|
| `spec/` | 仕様（SSOT）。人間とAIの合意対象 |
| `spec/decisions/` | ADR — 判断の履歴 |
| `impl/src/` | アプリ本体（GitHub Pages で公開する中身） |
| `impl/src/ghstore.js` | GitHub とのやりとり・接続コード・ファイルの形（`piano-log` と共通） |
| `impl/tests/` | テストと、偽の GitHub つき開発用サーバー |
| `impl/tools/` | 過去の記録の変換ツール |
| `original/` | 元の記録（リポジトリには入れない） |
